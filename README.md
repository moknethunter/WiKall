# WiKall · MokAsas Local Voice

تطبيق Android أصلي بواجهة عربية، مع وضع خادم محلي ووضع عميل في APK واحد. الإصدار 0.1.0 يختبر الاتصال المشفّر وإشارات الدعوة بين هاتفين. يدعم Android 10 فأحدث.

## تشغيل الاختبار

1. ثبّت `WiKall-Debug.apk` نفسه على الهاتفين.
2. وصّل الهاتفين بشبكة Wi-Fi واحدة أو وصّل الثاني بنقطة اتصال الأول. أبقِ التطبيق مفتوحًا على الهاتفين.
3. على الهاتف الأول، اختر **تشغيل كخادم · 1000** ثم **تشغيل الخادم**. اختر عنوان واجهة الشبكة المستخدمة إذا ظهرت عدة عناوين.
4. اختر **إنشاء وحفظ .mokprofile**، ثم انقل الملف إلى الهاتف الثاني عبر Bluetooth أو USB أو وسيلة مشاركة متاحة. يشير الملف إلى الرقم 1001، وصلاحيته خمس دقائق.
5. على الهاتف الثاني، اختر **استخدام ملف تعريف · 1001** ثم **استيراد .mokprofile**. طابق البصمة كاملة مع شاشة الهاتف الأول قبل الضغط على الاتصال.
6. اضغط **افحص الاتصال** لقياس زمن رسالة الذهاب والإياب المشفّرة. إذا تغيّر العنوان استخدم خيار IP اليدوي مع الحفاظ على بصمة الخادم.
7. أرسل دعوة من أحد الطرفين. جرّب الرفض ثم القبول اليدوي والإنهاء، واترك دعوة أخرى تنتهي بعد 30 ثانية.
8. أعد الاختبار مع فصل الإنترنت وتعطيل بيانات الهاتفين، مع إبقاء الشبكة المحلية متصلة. اختبر الراوتر والـ Hotspot بشكل مستقل. قد تمنع بعض إعدادات العزل وصول الهاتفين إلى بعضهما.

إذا استُهلك رمز الاقتران أو انقطع الاتصال بعد الاقتران، أنشئ ملفًا جديدًا. إنشاء ملف جديد يبطل الرمز السابق. يقتصر هذا الإصدار على مستخدمين ثابتين، خادم واحد وعميل واحد نشط.

## البناء

المتطلبات هي JDK 17، وAndroid SDK Platform 35، وBuild Tools 35.0.0، وبيئة Bash فيها Java وcurl وzip وunzip. اضبط `ANDROID_HOME` أو `ANDROID_SDK_ROOT` قبل بناء APK. يستخدم المشروع Gradle 8.11.1 وKotlin 2.0.20 وJUnit 4.13.2. عند توفر Gradle محليًا يمكن تعيين `GRADLE_HOME`.

```bash
./gradlew assembleDebug
./gradlew test
```

الـ APK في `build/outputs/apk/WiKall-Debug.apk`. التوقيع محلي لأغراض الاختبار. احتفظ بمفتاح Debug نفسه لترقية تثبيت تجريبي قائم. اعرض المشروع من Android Studio كملفات مصدر أو ابنِ من طرفية Android Studio بالأوامر أعلاه. تستخدم المهام أدوات SDK مباشرة، ويأتي مترجم Kotlin ومكتبات التشغيل المحددة من توزيع Gradle.

## الاتصال والأمان

يربط الخادم منفذ TCP بواجهة IPv4 محلية اختارها المستخدم. تستخدم الجلسة TLS 1.2 أو 1.3 ورسائل مؤطّرة بحجم محدود. تنشئ هوية الخادم داخل Android Keystore. يوقّع الخادم محتوى الملف ويتحقق العميل من سلامته، ثم يقارن المستخدم بصمة SHA-256 لبناء الثقة. يفحص العميل مفتاح شهادة TLS قبل إرسال رمز الاقتران. الرمز عشوائي، صالح مرة واحدة، محفوظ في الذاكرة، ولا يُطبع في السجلات. انقل ملف الاقتران باعتباره دعوة مؤقتة خاصة.

تفصل الشيفرة صيغة الملف، وهوية الخادم، ونقل الإشارات، وحالة الدعوة، والواجهة. يتضمن مسار الاختبار على JVM تبادل TLS حقيقيًا على loopback، وإعادة استخدام الرمز، ورفض البصمة الخطأ، وتعديل الملف وانتهاءه، والقبول والرفض والمهلة وإنهاء الدعوات. يتطلب مسار Android Keystore والرنين اختبارًا فعليًا على الهاتفين.

## النطاق المتبقي

الصوت عبر WebRTC، وتشغيل الخلفية وقفل الشاشة، واكتشاف NSD، وRoom، وإدارة الأجهزة الدائمة، والدمج مع MokAsas Server مراحل لاحقة. هذا الإصدار يختبر الدعوات فقط ولا يطلب إذن الميكروفون. استُخدمت واجهات Android الأصلية وبناء محلي بأدوات SDK بسبب عدم توفر تنزيل الاعتمادات وقت البناء. يتبقى نقل البناء إلى Android Gradle Plugin لتشغيل Android Lint وإضافة Compose وHilt واعتمادات المراحل التالية. بروتوكول TCP هنا خاص بإثبات الاتصال؛ دمج MokAsas Server يعتمد على بروتوكول مشروع الخادم الفعلي.
